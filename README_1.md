# 说明 1：应用层与硬件层的隔离是怎么规划的

> 本文是 **解读性说明**，回答「实验还在直写寄存器，是否和『应用层换 MCU / 换内核 / 换板子无感』的设想背道而驰」这个问题。

## 0. 结论先行

仓库把「学会硬件」和「隔离硬件」设计成 **先后两步**，而不是二选一：

- 第一阶段（001–014）刻意用寄存器直写，把硬件认知建满。
- 隔离的落点、三层边界、引入时机从第一天就立好，按需填充；抽象在第二、三阶段随 LL / HAL / 框架一层层加回来。

现在直写寄存器不是背离设想，而是在给设想打地基。

## 1. 隔离的落点已经画好，只是还没盖楼

三个目录各管一层，边界写在各自 README 里且口径一致：

| 层 | 目录 | 边界（原文口径） | 现状 |
|---|---|---|---|
| 纯逻辑 / 应用可复用件 | `common/` | 既不认识 MCU，也不认识 RTOS；不得 include 任何 vendor 头文件；「设计思想与 PAL 平台抽象的分层思想呼应」 | 空壳库，等真实需求回补 |
| 板级硬件 | `platform/<board>/` | 只负责硬件平台，不知道应用用哪个 RTOS；每块板只有一份 | startup / linker 已就位；`board` 模块（LED/按键引脚定义等板级封装）⬜ 规划中 |
| 框架配置与移植 | `frameworks/<fw>/` | 框架专属配置与移植（`port/`）放这里，不塞 common、不污染 platform | 第三阶段主战场 |

「LD1 在 PB0、B1 在 PC13」这类板级事实，最终要从实验 main.c 搬进 `platform/<board>/` 的 board 封装；实验只调用板级接口。换板子时按 platform/README 的规则：新增 `platform/<新板>/` 目录 + 顶层登记一行，应用代码不动。这个落点今天空着，是**还没到引入时机**，不是被遗忘。

## 2. 为什么现在不抽象

总纲是 ROADMAP 开头那句：**「工程能力在『有真实问题可解释时』引入，不为了基础设施本身暂停实验主线。」** 分层抽象被当作工程能力对待，遵循同一条纪律。具体三层理由：

1. **抽象只有在知道它隐藏了什么之后才有意义。** 根 README：同一外设从寄存器到 HAL 逐层递进，「这样以后看到 HAL，你知道它下面在干什么」。第 2 个实验就给 `led_on()`，建立的认知是「有个函数能点灯」，换个厂商库就废；寄存器认知才跟人一辈子。
2. **没有痛感的抽象是空壳。** 现在只有一块板、两个实验，此时设计 PAL 接口全是猜的。等第一阶段把 GPIO / EXTI / timer / UART / DMA 都摸过，接口需求被真实实验「逼」出来，抽象才贴合实际。E1 的每一项都围绕 001 的真实产物做、「不提前造基础设施」，是同一条纪律的先例。
3. **L1→L2→L3 本身就是一部抽象递增史。** 同一外设亲手写三遍：裸寄存器、厂商 LL、HAL。写完三遍，「抽象层替你做了什么、代价是什么」从概念变成体感。

## 3. 「换 MCU / 换内核 / 换板子无感」靠什么实现

把这句话拆成三个粒度，仓库各有安排：

- **换板子**（同 MCU，引脚 / 布局不同）：靠 `platform/<board>/` 的 board 封装。板级事实沉在板级目录，且「以 docs/board/ 官方资料为准」；应用只认接口不认引脚。
- **换 MCU**（同内核，如 F4→G4）：靠 L3 的 HAL。CubeF4 自带 README 对 HAL 的定义即「a set of APIs ensuring maximized portability across the STM32 portfolio」——厂商已造好跨 MCU 移植层，而 L1/L2 攒下的知识让你能审查它、不信它。
- **换内核 / 换架构**（ARM→RISC-V、裸机→RTOS）：靠第三阶段框架与 `frameworks/<fw>/port/`。FreeRTOS 的 portable 目录、Zephyr 的 devicetree 都是业界现成的差异隔离层；仓库对 Zephyr 明确规划独立 workspace（west + devicetree 与 CMake 体系不兼容）——说明隔离的边界与代价是被认真考虑过的。

贯穿始终、真正「换什么都无感」的是 `common/` 里不认识任何硬件的纯逻辑。它现在空着，等 013 ring buffer 这类真实需求出现才回补——仍是同一条纪律。

## 4. 一句话总结

第一阶段用寄存器把硬件认知建满，第二、三阶段用 LL / HAL / 框架把抽象一层层加回来；common / platform / frameworks 的三层边界从第一天立好、按需填充。**什么时候兑现**是时机问题，**兑不兑现**从来不是问题。
